## Integration findings

- The feature branches touched the same catalog, renderer, IPC and documentation surfaces. The integration preserves their separate capability gates and uses the existing physical-owner reservations for reviewed database changes. Source and test paths stay in the combined branch.
- Operation History originally had no A1 or A2 receipt. It now includes principal changes and administration with an engine, timing and outcome only. A completed or partially applied change, reported maintenance issues and an unknown outcome have distinct labels. Synchronous preflight refusals do not create a misleading unknown entry. SQL, targets, passwords and server errors stay out of these receipts.
- The A4 UI review identified unreachable cancellation, lost renewal state across tabs, keyboard focus, browser-stage wording and truncated registration IDs. The corrected package keeps cancellation with its originating attempt, distinguishes opening, waiting, finishing, cancellation and expiry, restores focus, and shows complete IDs at 125% and 200%.
- Authentication and transport are independent checks. The token provider is attached inside the database host, and new TDS opens resolve the current grant through the existing transport. Connection profiles carry public registration IDs and an optional account hint. Tests for protected sessions, private history and the TLS identity of direct and SSH connections use the local engines. The Entra connector regression reaches an actual loopback forwarding socket while retaining the logical TLS hostname and refusing unintended destinations. Live Azure routes still need separate evidence.
