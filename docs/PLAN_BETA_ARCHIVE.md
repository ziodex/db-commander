# Db Commander beta plan

Scope frozen on **20 October 2026**, starting from development runtime `5395b1f`. Beta is intended for daily development use with explicit limitations. It is not released or certified on every target yet. The checklist below is the single source of truth for beta readiness; dated implementation/test reports are evidence, not additional backlogs.

Bug fixes, regression tests, qualification and release documentation remain in scope. New engines, expanded workflows and removal of the documented limits wait until after the initial beta. A runtime fix requires rebuilding the candidate and repeating affected checks; an earlier package's results do not certify changed bytes.

## Current repository

Development now takes place on [`ziodex/db-commander:development`](https://github.com/ziodex/db-commander/tree/development) with fresh Git history. Version 0.2.0 remains a developer preview with no published release. [GitHub Actions](GITHUB_ACTIONS.md) validates development/main pushes and pull requests; signing remains an explicit, gated main run. The earlier source SHAs and Azure results in this checklist refer to archived milestones and do not certify the current GitHub commit. The bootstrap `main` history still needs a deliberate maintainer migration before the first main release.

## Frozen scope

| Area | Included in the initial beta |
| --- | --- |
| Connections | Saved profiles, folders/tags/favorites, explicit reconnect, optional OS-stored passwords, verified TLS and pinned SSH routes. Each query tab owns its physical session. |
| Engines | PostgreSQL, MySQL, MariaDB, SQL Server, SQLite, DuckDB and Oracle Thin mode, within the tested versions/capabilities. These are candidate targets until the relevant native gates pass. Azure SQL remains an **experimental profile**, not a qualified cloud service. |
| Workspace/editor | SQL files, autosave/recovery, multiple windows, tabs/pinning/order, up to four split editors, themes, zoom, settings exchange, shortcuts, formatting, bounded completion, snippets and bound parameters. |
| Execution/data | Statement/selection/script execution, precise values, multiple results, cancellation, explicit transactions, paginated table browsing, conservative keyed editing, value inspection and foreign-key navigation. No automatic SQL replay. |
| Tools | Existing schema inspection/change previews, plans, diagrams, same-engine schema comparison, bounded keyed data comparison, migration export, query builder, session/lock controls and rollback observation. Existing privilege/type/scope restrictions apply. |
| Transfers | Existing CSV/JSON/SQL INSERT workflows, streaming full-result exports, cancellation and engine-specific native backup/restore. Destructive or billed operations retain explicit review. Experimental Azure recovery-copy behavior is not qualified for beta support. |
| Desktop delivery | macOS Intel x64 and Apple Silicon arm64 DMG/ZIP; Windows x64 NSIS; Linux x64 DEB/RPM/AppImage. Opt-in minimize to tray. Signed Mac/Windows distribution follows the existing main-only release gates. |
| Updates | **Manual updates only.** Close the app after settling transactions, preserve a closed-profile backup and install the reviewed platform package. No in-app updater, forced restart or downgrade guarantee. See [beta notes](BETA_NOTES.md). |

## Accepted beta limits

- Catalog previews retain approximately 2,000 objects and 10,000 column rows. Filters search the loaded preview; omitted objects are not made reachable by filtering. SQL can still address them directly. The 20,000-table tests verify safe bounded loading, not complete catalog navigation. Pagination/server-side object search is deferred.
- Query previews retain up to 1,000 rows per result set and 8 MiB of text per execution. These are retained-data limits, not server-work limits. Use the separate full-result export workflow for larger outputs.
- A query buffer is limited to 1,000,000 characters; a workspace to 20 tabs and 5,000,000 SQL characters. Grid editing/comparisons, diagrams and large values retain their documented conservative bounds.
- Azure SQL has local TDS/profile coverage only. Live authentication, firewall/redirect/private endpoints and recovery copies have not been qualified. Entra tokens are supplied and renewed manually; integrated authentication and interactive cloud login are excluded.
- Qualification applies to named engine versions, native clients and tested workflows. A protocol-compatible service, another server version or an emulated worker is not implicitly supported.
- Crash and disk-full recovery are tested faults. Physical power loss, damaged devices, system-volume exhaustion and arbitrary filesystems are not certified durability guarantees.

See [user-facing beta notes](BETA_NOTES.md), [current implementation](IMPLEMENTATION.md) and [driver evidence](DRIVER_TESTING.md) for complete limitations. The original product/architecture roadmap and dated milestones are preserved in [plan history](PLAN_HISTORY.md).

## After the initial beta

Catalog pagination/server-side search; new engines and broader server-version/authentication coverage; qualified live Azure service support; automatic updates and update rollback; independent result panes/cross-window tab transfer; deeper completion and administration; broader import/export formats; historical upgrade matrices once a published baseline exists; broader physical-device/filesystem fault qualification. Existing documented safety limits remain in place until each expansion has its own design and validation.
